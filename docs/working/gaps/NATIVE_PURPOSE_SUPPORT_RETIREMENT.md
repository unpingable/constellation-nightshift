# Native purpose support R4 migration

Current source parser now selects `nq.diagnostic-purpose-support/v1`, never the
classic wire by fallback. `parse_for_request` binds the exact consumer, purpose,
subject/scope digest, claim and requested time; checks request/receipt integrity
and exclusive expiry; and requires configured NQ source custody. Hashes alone
do not authenticate arbitrary files.

`historical_readonly` is explicitly historical retained-claim consideration,
not current world health. `continue_observing` remains fail-closed when source
currentness cannot be established. Original continuity-gated semantics are NOT
silently weakened to make this increment appear complete. Missing native clock
comparison and `continuity_rely_eligible` producer remain retirement obligations.

All old vectors and projection tests remain, using the explicitly named
`parse_historical_checked` archive reader. This does not authorize their use as
current testimony. Native tests consume fixtures generated by an actual NQ-ng
local engine/store qualification run, including exact request, refusal, expiry,
substitution and source-currentness uncertainty. No classic executable is
invoked. Original M2 and classic qualification stay on their original revisions.

## Existing currentness composition

`qualify_current_purpose` now composes native historical factual eligibility
with the EXISTING `PresentEvidencePortV1`. It binds the exact v2 artifact bytes,
validated DiagnosticInputs identity, claim/purpose via NQ decision identity,
subject/scope, current cycle/nonce and configured support authority. Only a live
response matching the entire query, current on the authority's receiver clock,
with nonempty evidence references permits read-only continuation. Missing,
unknown, expired, contradictory or mismatched support cannot become Fresh.

The result retains NQ decision and qualified present-support separately. No
NQ source-clock guarantee is invented, no historical receipt is relabeled, and
no action authority is granted. Tests use actual native local-store factual
evidence with an explicitly labeled qualified-port boundary fixture; this is
not a production Pulse deployment witness. The continuity-gated specialized
claim remains separate and cannot be satisfied by this base-role composition.

## Named Continuity prerequisite implementation

The remaining source is Continuity MEMORY `rely_export.v0`, not Standing
substrate succession. Native NQ now qualifies its exact external projection as
`nq.continuity-memory-support/v1`, preserving source premises/tiers/nonclaims and
eligible vs noneligible vs indeterminate. The continuity consumer accepts only
the exact principal/purpose/subject-bound named `continuity_rely_eligible`
qualification disclosed by NQ. It adds that qualification identity alongside
the primary diagnostic in the existing live present-evidence query. Missing,
substituted, unrelated or expired current support cannot satisfy the gate.

This replaces the previously recorded missing producer prerequisite without
redefining historical evidence as current or turning NQ into temporal authority.
Actual Continuity producer and NQ qualification are exercised on isolated local
fixtures; the present-evidence adapter remains an explicitly labeled qualified
boundary fixture, not a deployment qualification.
